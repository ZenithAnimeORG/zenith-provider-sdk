# Zenith Provider SDK & Documentation

Official SDK and developer documentation for building third-party media providers, catalog scrapers, trackers, and subtitle plugins for the [Zenith](https://github.com/ZenithAnimeORG) media player ecosystem.

Zenith plugins are authored in **TypeScript** using the portable `@zenith/sdk`, bundled with `esbuild`, and executed in-process inside Zenith's isolated **QuickJS** runtime engine.

---

## Documentation Website

The complete bilingual documentation website (English & Russian) is built with **VitePress** and features auto-generated API references generated by **TypeDoc**:

```bash
# Generate TypeDoc API reference from TSDoc comments
npm run docs:generate

# Start local VitePress development server
npm run docs:dev

# Build production static documentation site
npm run docs:build
```

Documentation website contents:
- **Getting Started**: Setup with `zenith-provider-template`, running Vitest, packaging `.zpk`.
- **Manifest V2 & Package Envelope**: Envelope limits (32 MiB uncompressed, 5 MiB JS, max 100 entries, no native binaries).
- **Provider Capabilities**: Catalog search, direct media streams, BitTorrent discovery, subtitles, skip timings.
- **Cheerio DOM Parsing**: Fast in-bundle HTML querying via `@zenith/sdk/dom`.
- **Network & Host Broker**: Brokered HTTP requests (`context.fetch`), allowlists, anti-bot handling.
- **Testing & Fixtures**: Deterministic offline unit testing with Vitest.

## Kotlin SDK (Internal Host Runtime)

The Zenith Provider ecosystem is modular and plugin-driven. This SDK defines provider contracts, a typed worker adapter, protocol-v1 messages, host and worker session loops, broker-backed worker context, and bounded JVM JSON-lines transport. It does **not** implement the application host capability broker, a native process launcher, or operating-system sandbox. Zenith.App currently fails closed: provider installation and execution remain unavailable until a platform's native isolation and broker are implemented and verified. The wire protocol alone is not a security boundary.

Provider package checksums detect transfer or content mismatches; they do not authenticate publishers. Unsigned community packages are intentional. Do not treat optional package signatures or manifest host declarations as protection unless a verified host runtime enforces them.

### Modules

- **`:provider-sdk`**: Core interfaces, data models, manifests, settings schemas, and contract models.
  - `ZenithProvider`: Lifecycle interface for all plugins (`initialize`, `dispose`, `test`, `executeAction`, `probeStatus`).
  - `MediaSourceProvider`: Resolves direct and embed video streams (`getSources`, `resolveStream`).
  - `CatalogProvider`: Search, discovery, popular releases, and episode catalog listings.
  - `TorrentSourceProvider`: Resolves torrent magnets and peer swarms.
  - `SubtitleSourceProvider`: Queries external subtitle tracks (`.ass`, `.vtt`, `.srt`).
  - `SkipTimingsProvider`: AniSkip/AnimeSkip anime opening/ending skip timecodes.
  - `TrackerProvider`: Synchronizes watch progress with external tracking platforms.
  - `ImportProvider`: Batch imports user watchlists and bookmark history.
  - `StreamExtractor`: Modular iframe/embed video extractor interface.
  - `ProviderWorkerSession` / `ProviderWorkerRuntime`: Correlated host/worker session loops with bounded concurrency, deadlines, cancellation, and checksummed chunk transfer.
  - `ProviderWorkerBrokerContext`: Worker `ProviderContext` whose Ktor HTTP requests, mirrors, stream resolution, and setting updates are routed through IPC.
  - `JvmProviderWorkerFrameTransport`: Size-limited UTF-8 JSON-lines framing over injected JVM streams.

- **`:provider-sdk-testkit`**: Deterministic test fixtures and contract verification harnesses.
  - `ProviderContractTestBase`: Verifies plugin adherence to SDK invariants.
  - `FakeProviderContext`: In-memory context simulating provider settings and mirror selection.
  - `MockProviderHttpClient`: Ktor MockEngine DSL for synthetic HTTP responses without external network access.

## Installation

Artifacts are currently consumed from Maven Local; they are not available from Maven Central. Publish the SDK and testkit locally first:

```bash
git clone https://github.com/ZenithAnimeORG/zenith-provider-sdk.git
cd zenith-provider-sdk
git checkout 31352b446253ce2aaa657f5cfe5b3f176d66b572
./gradlew publishToMavenLocal
```

Then add Maven Local to your Kotlin Multiplatform or JVM Gradle build:

```kotlin
// settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        mavenLocal()
        mavenCentral()
    }
}

// build.gradle.kts
dependencies {
    implementation("com.pilldev.zenith:provider-sdk:0.1.0")
    testImplementation("com.pilldev.zenith:provider-sdk-testkit:0.1.0")
}
```

The SDK artifact and provider contract identifiers are both at internal version `0.1.0`. These artifacts are not publicly released; breaking changes are expected during development, so no artificial major-version bump is needed. Consumer CI workflows pin the SDK source commit separately to make builds reproducible; update those pins deliberately when adopting a newer SDK commit.
